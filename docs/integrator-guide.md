# Integrator guide

This guide is for the developer who connects CookieConsentManager to a Thelia 3 theme.
With it you can check what the module injects, override its templates, make your own code wait for consent, move a hard-coded Google Tag Manager, declare services from another module, and run the tests.

Installation and the basics are in the [README](../README.md). The administrator side is in the [administrator guide](administrator-guide.md). The formats shared by the engine, the server and the templates are in [runtime contracts](runtime-contracts.md).

## What the module injects

| Flexy hook | Content |
|------------|---------|
| `layout.head.top` | the published configuration (`<script type="application/json" id="ccm-config">`), an inline script (Consent Mode `default` then `update`, the `ccmQueue` array, the `ccm_consent_ready` event), `<link rel="stylesheet" id="ccm-style" href="/ccm/<hash>.css">` (the stylesheet of the module, a file named after its own hash) and `<script defer src="/ccm/<version>-<hash>.js">` |
| `layout.body.top` | the banner (`hidden`), the placeholder template, `<script type="application/json" id="ccm-services-meta">` (controller and policy address of the media services, and the purpose labels under `@purposes`, read by the engine for placeholders), `<script type="application/json" id="ccm-messages">` (engine messages in the visitor's language), the optional floating button |
| `layout.footer.top` (3.0, 3.1) or the `footer_links` slot (3.2 and later) | the "Manage my cookies" link |

- Nothing is injected until a version is published (the draft preview aside).
- The preferences panel is not in the page. The engine fetches it from `GET /ccm/panel/<version>-<hash>-<locale>.html` the first time the visitor opens it. Only the draft preview and the audit carry it inline.
- The engine, the stylesheet and the panel are served by versioned routes with an `immutable` cache. A stale hash answers a 302 to the current address. Nothing is written to `public/`.
- A theme without the Flexy `layout.*` hooks shows no banner. Call `theme_hook('layout.head.top')` and `theme_hook('layout.body.top')` in its `base.html.twig`. The dashboard raises an alert when the active theme does not call one of them.
- The no-JavaScript preferences page is `GET /ccm/preferences`.
- All module URLs are generated by the router, so a shop installed in a sub-directory works. Template overrides receive `preferences_url`.

## Disabling the module and the Twig guard

Once the module is disabled, the Twig functions `ccm_has_consent`, `ccm_has_purpose_consent`, `ccm_placeholder` and `ccm_open_link` no longer exist. A template that calls them fails with `Unknown "ccm_has_consent" function` on the whole site. `is defined` does not protect, because the error comes at compile time.

Put the calls in a partial of the theme and include that partial only when a probe succeeds. The probe includes the module template `guard.html.twig` (it renders `1`) with `ignore missing`. The template resolves only while the module is active.

```twig
{% set ccmProbe %}{% include 'CookieConsentManager/guard.html.twig' ignore missing %}{% endset %}
{% if ccmProbe|trim %}
    {% include 'partials/consent-aware.html.twig' %}
{% else %}
    {# module absent or disabled: fallback without consent (nothing, or neutral content) #}
{% endif %}
```

Never override `guard.html.twig` in the theme: the theme copy would always be found and the guard would no longer see the deactivation. Checked on Thelia 3.0.0: with the module disabled the page answers 200 with the fallback, and with the module active the partial is included.

## Flexy child theme

A module template is overridden in the active theme or its parent. The prerequisites below were observed on Thelia 3.0.0 (Flexy 1.0.3). They belong to Thelia, not to the module. Check your version's documentation, and check them again on 3.1 to 3.3, where they were not replayed.

1. `templates/frontOffice/<child>/template.xml` with `<parent>flexy</parent>` and an `<authors>` section (name, company, email, site). Without it the core throws a `TypeError` (`TemplateValidator`) and the site and the console fail.
2. Assets: Flexy is served by AssetMapper. A child theme that provides none fails with a 500 (Tailwind `assets/styles/app.css` not found, or entry "app" not found without `importmap.php`). Provide `assets/` and `importmap.php`, as copies or symlinks to those of Flexy. With the symlinks, the compiled Tailwind sheet of Flexy is served to the child theme (seen on 3.1.6). The styles specific to the child theme are compiled as the Thelia documentation describes.
3. `components/`, `form/`, `blocks/`: link to those of Flexy when the child theme does not redefine them.
4. Activation: the active theme is set in the back-office (setting `active-front-template`). When the environment variable `ACTIVE_FRONT_TEMPLATE` is defined (`.env.local`, server), it wins over the database value (seen on 3.1.6, `Config::getValue()` reads `$_ENV` first). Change the variable, then clear the cache.

The CSS of the module is self-contained and stays correct when the child theme is not styled.

## Overriding a template

Templates are resolved by the bare path `CookieConsentManager/<name>` (never `@CookieConsentManagerModule`), in this order: active theme, parent theme, module. A child theme provides only the templates it changes.

```
templates/frontOffice/<theme>/CookieConsentManager/
├── banner.html.twig            first level (bar or modal)
├── preferences-panel.html.twig second level
├── placeholder.html.twig       placeholder of a service
├── open-link.html.twig         Twig helper ccm_open_link and the footer link
├── floating-button.html.twig   floating button (option)
└── preferences-page.html.twig  stand-alone page /ccm/preferences (no JavaScript)
```

The originals are in `templates/frontOffice/flexy/CookieConsentManager/` and `templates/frontOffice/default/CookieConsentManager/` (neutral fallback).

1. Copy the original to the theme, keeping only the templates you change.
2. Start the file with the marker `{# ccm-templates:1 #}` (only whitespace may precede it). The marker uses a colon: `{# ccm-templates/1 #}` is not recognised.
3. Keep the `data-ccm-*` attributes listed below. The engine never reads a CSS class, so you can add your own classes.
4. Use the template variables. `ccm_contract` (`ccm-templates/1`) is a Twig global available in every template while the module is active.
5. Clear the cache (`php Thelia cache:clear`), reload the shop, then open the module dashboard. An override gives the information "template(s) overridden". A missing marker, or one that is not `1`, gives a red alert.
6. Publish again. Templates are part of the served hash, so after a theme deployment the alert "rendering differs from the published version" is resolved by publishing.
7. At each module upgrade, compare your copies with the originals. They are not updated automatically. If the contract number changes (`ccm-templates:2`), the red alert says so.

"Accept all" and "Reject all" must keep the same component, the same class and the same colours. The banner keeps `role="dialog"`, a title and an accessible name, and the modal traps focus. The contrast check of the back-office does not cover a rewritten template.

### Template variables and required attributes

| Template | Variables | Attributes the JavaScript needs |
|----------|-----------|---------------------------------|
| `banner` | `ccm_contract`, `layout` (`bar` or `modal`), `merchant_name`, `purposes` (`code`, `label`, `description`, `locked`, `services`), `texts` (including `colon`, `purposes_intro`, `measurement_notice`, `measurement_object`), `close_enabled`, `floating_button`, `policy_url`, `preferences_url`, `locale`, `language`, `mode`, `colors`, `exempt_services` | root `data-ccm-banner`; buttons `data-ccm-action` with the value `accept_all`, `reject_all`, `open` or `close_reject`; `data-ccm-open` and `data-ccm-open-exempt` on the button that objects to exempt measurement; scrolling text area `data-ccm-scroll` |
| `preferences-panel` | same; each `service` carries `controller`, `policy_url`, `cookies` and `cookie_details` (list of `name`, `duration`); `exempt_services` | root `data-ccm-panel`; `data-ccm-purpose="<code>"`, `data-ccm-service="<key>"` and `data-ccm-exempt="<key>"` on the `role="switch"` toggles; `data-ccm-action` with the value `save`, `accept_all`, `reject_all` or `close`; `data-ccm-consent-id`; `data-ccm-withdrawn` (sentence about remaining third-party cookies, shown after a refusal); `data-ccm-exempt-group` (exempt measurement group, expanded by `data-ccm-open-exempt`) |
| `placeholder` | `ccm_contract`, `service` (`key`, `name`, `purpose_label`, `controller`, `policy_url`), `texts`, `attributes`, `src`, `colors` | root `data-ccm-placeholder="<key>"`; `data-ccm-action="service_allow"` with `data-ccm-service`; `data-ccm-open`; `data-ccm-src` (an `https://` or protocol-relative `//host` address, anything else is ignored) and `data-ccm-attr-*` for an iframe (only plain attributes are restored: `class`, `id`, `width`, `height`, `title`, `allow`, `allowfullscreen`, `frameborder`, `loading`, `referrerpolicy`, `name`, `style`, `scrolling`, `sandbox`, `videoid`, `aria-*`, `data-*`; never `on*` or `srcdoc`); `data-ccm-if-policy` around the policy link (the engine removes it when the address is neither a path nor an http(s) URL); buttons in `.ccm-js-only`, link to `/ccm/preferences` in `.ccm-nojs-only` |
| `open-link` | `ccm_contract`, `label`, `wrapper` | `data-ccm-open` |
| `floating-button` | `ccm_contract`, `label`, `position`, `colors` | `data-ccm-open` |
| `preferences-page` | variables of the second level plus `head`, `body`, `language` | full page: start from the original |

- `texts` holds `title`, `body`, `accept`, `reject`, `customize`, `close`, `policy`, `preferences`, `allow_service`, `blocked`, `colon`, `remembered` and more. Start from the original template for the full list. Values are already translated for the visitor's language.
- CSS classes used by the module stylesheet (not read by the engine): `ccm-foot` (banner footer, outside the scrolling area), `ccm-intro` and `ccm-purposes` (list of active purposes), `ccm-js-only` and `ccm-nojs-only` (the head script sets the class `ccm-js` on `<html>`).
- The first-level banner always keeps its buttons visible: the text scrolls, the actions stay fixed.

### Languages and copied templates

Templates contain no hard-coded French or English. Every label goes through the Thelia translator, domain `cookieconsentmanager.fo.flexy`, files `I18n/frontOffice/flexy/<locale>.php` (fr_FR, en_US, de_DE, nl_NL, es_ES). The domain is named after the module folder and not after the active theme, so a child theme uses it without doing anything. Another active language receives the English message, since the message id is the English text.

For a theme that copied templates:

1. Replace each hard-coded colon of a label with `{{ texts.colon }}` (French: space, colon, space; other languages: colon, space). Example: `{{ texts.controller }}{{ texts.colon }}{{ service.controller }}`.
2. Pick up newer elements of the original (purpose list before the text, `ccm-foot` footer, exempt measurement sentence, no-JavaScript link of the placeholder, `data-ccm-withdrawn`). An older copy stays valid but does not show that information.
3. Editable texts (`texts.title`, `texts.body`, and so on) are already resolved by the module: the administrator's entry in the language, else the translated default of the language, else the English entry, else the English default. Do not reimplement this fallback.
4. The engine messages (placeholder, confirmations) come from `#ccm-messages`, emitted with the `layout.body.top` hook. A theme that keeps that hook receives them. Without the element the engine falls back to English.
5. A new template label is declared in `Front/FrontTexts.php` (`LABELS`) and in the six translation files. `TranslationCatalogueTest` checks that keys and `%parameters%` are identical in the six.

The module provides three Thelia translation domains, each with six files: `cookieconsentmanager` (validation messages, `I18n/<locale>.php`), `cookieconsentmanager.bo.default-twig` (back-office) and `cookieconsentmanager.fo.flexy` (front). The German, Dutch, Spanish and Italian translations were not reviewed by a native speaker.

## Making code depend on consent

| Need | Tool |
|------|------|
| Load a third-party script from a template | `<script type="text/plain" data-ccm-service="<key>">` (or `data-ccm-purpose`) |
| Run JavaScript on grant | `ccmQueue.push(() => CookieConsentManager.onConsent('<key>', fn))` |
| React to any change, withdrawal included | `CookieConsentManager.onChange(fn)` or the `document` event `ccm:consent` |
| Show a block only when granted (server render) | `{% if ccm_has_consent('<key>') %}` behind the guard |
| Embedded video or map | `ccm_placeholder('<service>', {src, title, ...})` |
| Reopen the preferences | `ccm_open_link('Label')` or any element with `data-ccm-open` |
| Record a choice from code | `CookieConsentManager.setConsent({services: {crisp: 1}})` (source `api` in the registry) |

- The engine script is `defer`. Use `window.CookieConsentManager` only after `ccm:ready`, or go through `ccmQueue`, which exists from the `<head>`.
- `onConsent` is not called on withdrawal. Use `onChange`.
- A page that calls `ccm_has_consent` depends on the visitor's cookie, so do not put it in a shared cache. The Thelia 3.3 shared cache serves only visitors without a cookie.

### JavaScript API

The inline head script creates the array `window.ccmQueue` before the engine loads. The engine drains it when ready, and after that `ccmQueue.push(fn)` runs `fn` immediately.

```js
window.ccmQueue = window.ccmQueue || [];
window.ccmQueue.push(() => {
  CookieConsentManager.onConsent('crisp', () => window.initChat());
});
```

| Method of `window.CookieConsentManager` | Role |
|------------------------------------------|------|
| `open()` | opens the preferences panel (focus returns to the caller) |
| `hasConsent(service)` | `true` when the service is granted (exempt measurement: true until the visitor objects) |
| `hasPurposeConsent(purpose)` | `true` when the purpose is fully granted (a partial purpose is not) |
| `onConsent(service, cb)` | calls `cb` at once when the service is already granted, then at each new grant; not on withdrawal. Before `ccm:ready` the call is queued |
| `onChange(cb)` | `cb({purposes, services, version})` at each choice, withdrawal included; returns an unsubscribe function |
| `setConsent({purposes, services, exempt})` | records a choice (source `api`, traced in the registry); returns a promise. Values: `1` granted, `0` refused. Reserved for the code of the site: never call it on behalf of a visitor who has not chosen |
| `getConsentId()` | the visitor's consent identifier, or `null` |

Events on `document`: `ccm:ready` (`{purposes, services, version}` once the engine has started), `ccm:consent` (same detail after each action of the visitor), `ccm:service:<key>:allowed` (`{service}` when a service has just been granted). The `dataLayer` events are in [runtime contracts](runtime-contracts.md#datalayer-events).

PHP: the event `CookieConsentManager\Event\ConsentRecordedEvent` (`entry`, `firstChoice`) is dispatched after each write to the registry.

### Twig API

| Function | Role |
|----------|------|
| `ccm_has_consent(service)` | reads the cookie on the server; `false` without a choice, without a published version, in preview and in audit |
| `ccm_has_purpose_consent(purpose)` | same for a purpose |
| `ccm_placeholder(service, attributes)` | placeholder of a service. `src` becomes the source restored on "Allow"; other attributes are rendered as `data-ccm-attr-<name>`. Empty string when the service is not active in the published version |
| `ccm_open_link(label)` | link that reopens the preferences (default label: the "preferences" text of the language). Empty string when nothing is published |

```twig
{% if ccm_has_consent('crisp') %}<script src="{{ crispUrl }}"></script>{% endif %}
{{ ccm_placeholder('youtube', {src: 'https://www.youtube-nocookie.com/embed/ID', title: 'Product video', width: 560, height: 315}) }}
{{ ccm_open_link('Manage my cookies') }}
```

Both consent functions apply the renewal delay and the last substantial version, as the browser does.

`ccm_placeholder` with `src` (iframe): on "Allow" the native iframe is restored with the original attributes, and when the service is withdrawn the placeholder comes back without a page reload.

`ccm_placeholder` without `src` (a block that is not an iframe): the placeholder shows the service, its purpose and the "Allow" button, and the choice is recorded. After "Allow" the block is emptied, its `data-ccm-attr-*` attributes move to the element (for example `class` and `videoid`, as given in the call), and the upstream fragment of the service renders it. For a video player the safest way is the markup of the catalogue. The "Purposes and services" screen of each media service shows the "HTML to paste in your page" (for YouTube, `<div class="youtube_player" data-videoID="...">`), and the placeholder is then produced and lifted by the service itself.

When an exempt measurement tool (for example Matomo) already runs and the visitor refuses, the page reloads once to stop the script that has already executed (setting `reload_on_script_withdraw`, on by default).

### Hard-coded scripts

A script you place yourself in a template must be tagged so that it does not run before the choice:

```html
<script type="text/plain" data-ccm-service="gtag">/* runs when the gtag service is granted */</script>
<script type="text/plain" data-ccm-purpose="analytics" src="https://example.test/pixel.js"></script>
```

- `data-ccm-service="<key>"`: re-enabled when that service is granted. `data-ccm-purpose="<purpose>"`: re-enabled when the purpose is fully granted. Other attributes (`src`, `async`) are copied and `type` is removed.
- An untagged script is never intercepted. The Verification page shows it (domain "loaded outside the module").
- On withdrawal, the page reloads when the option "Reload the page when a script consent is withdrawn" is on (default). Otherwise the module does not undo a script that has already run.
- The iframes of the media services are replaced by a placeholder automatically (option "Automatically block embedded iframes", on by default), only when the service is active and published. This covers 41 of the 94 media services of the catalogue: the ones whose embed is an iframe with an identifiable host. The hosts and paths come from the fragments (`Resources/catalogue/embed-rules.json`, regenerated by `node tools/catalogue/embed-rules.mjs`) plus the embed hosts of YouTube, Vimeo, Dailymotion and Google Maps. A host alone is never enough on a shared domain (`www.google.com` also serves reCAPTCHA), so each rule carries path prefixes, and the longest one wins.
- The answers of a LiveComponent are rewritten like a page. The browser morphs them into the page, and an untouched iframe would bypass the consent. ESI fragments are rewritten too, as are HTML responses of controllers and pages of other modules.
- Not rewritten: the answers to a request carrying `X-Requested-With`, and iframes created in JavaScript. For these, use the placeholder template or the `ccmQueue` queue.
- Not rewritten server-side, with the reason:
  - the service has no iframe, it loads a script or a widget (the placeholder of its fragment applies once the page runs): `addthis`, `addtoanyshare`, `adsense`, `adsensesearch`, `adsensesearchresult`, `aduptech_ads`, `calendly`, `clicmanager`, `criteo`, `datingaffiliationpopup`, `disqus`, `facebook`, `facebookcomment`, `facebookcustomerchat`, `facebooklikebox`, `fillout`, `googlemaps`, `googlepartners`, `gplus`, `gplusbadge`, `hcaptcha`, `intercomChat`, `kwanko`, `linkedin`, `m6meteo`, `pinterest`, `pipedrive`, `prelinker`, `pubdirecte`, `recaptcha`, `rumbletalk`, `seamlessaccess`, `shareaholic`, `shareasale`, `sharethis`, `statcounter`, `tidycal`, `tiktokvideo`, `trustpilot`, `twitter`, `twitterembed`, `twittertimeline`, `twitterwidgetsapi`, `vshop`, `xandrconversion`, `xandrsegment`;
  - the iframe address is typed by the editor, so no host is known in advance: `gallica`, `geoportail`, `googlemapsembed`, `helloasso`, `iframe`, `openstreetmap`, `podcloud`. For these, wrap the iframe with `ccm_placeholder('<key>', {src: ..., title: ...})` in the template, or tag the iframe by hand.

## Moving a hard-coded GTM

Starting point: the Google Tag Manager snippet and its `<noscript>` are in the theme's `base.html.twig`, or the Thelia module `GoogleTagManager` is active. The container then loads before any choice.

1. Note the container ID (`GTM-XXXXXXX`) from the snippet.
2. If the Thelia module `GoogleTagManager` is active, disable it. The "Google Tag Manager" service of this module refuses to activate while that module is active (red alert on the dashboard).
3. Remove from the theme the `<script>` snippet and the `<noscript><iframe src="https://www.googletagmanager.com/ns.html?...">` block (the `noscript` loads GTM without consent). Remove any hard-coded `gtag.js` too.
4. In the back-office, "Purposes and services": enable "Google Tag Manager" and enter the ID. Do not also enable "Google Analytics 4" when GA4 is already configured inside the container: enabling both raises the alert "gtag is loaded twice".
5. "Consent Mode": leave "Basic" (no Google tag before consent). In "Advanced", GTM loads before the choice, so have it checked by your legal adviser.
6. In GTM, use the built-in consent checks of the tags and the triggers `ccm_consent_ready` (every page) and `ccm_consent_update` (change). Do not create a custom consent tag: the module is the only source of `consent` commands.
7. Publish, clear the cache, open a private window: no request to `www.googletagmanager.com` before the choice.
8. Run the Verification before and after "Reject all": no Google domain "before consent" remains. Check with Tag Assistant: `default` denied, then `update` granted, before any hit.

GTM loads on the first grant of the `analytics` or `ads` purpose. The `personalization` purpose alone does not load it.

## Google Consent Mode v2

- Basic (default): no Google tag loads before consent to a purpose that carries an `analytics_storage` or `ad_*` signal. `gtag('consent', 'default', ...)` is sent once at the top of `<head>` (the four main signals `denied`, `security_storage` `granted`). Then comes the `update` read in the browser if a choice exists, then the `ccm_consent_ready` event.
- Advanced: Google tags load before the choice (pings without cookies, `wait_for_update` 500 ms by default) and the region defaults (ISO 3166) become effective. Moving from basic to advanced needs a confirmation checkbox, the red dashboard alert stays permanent, and the Verification reports Google requests before the choice. Have it validated by the site's legal adviser.
- A `granted` default is refused (except `security_storage`) for a European region or a line without a region ([decision 002](decisions/002-european-scope-and-retention-cap.md)).
- Stale choice: while the renewal delay has passed, or a substantial version is later than the choice, no `granted` update is sent and `ccm_consent_ready` carries no granted purpose. "Reject all" and withdrawal send `denied` on every managed signal.
- Purposes and signals: audience measurement `analytics_storage`; advertising `ad_storage`, `ad_user_data`, `ad_personalization`; personalization `functionality_storage`, `personalization_storage`; `security_storage` always `granted`. Options: `ads_data_redaction`, `url_passthrough`, Microsoft UET (`ad_storage`).
- Checks: (1) Tag Assistant on the home page: `default` denied then `update`, before any hit; (2) Network tab, parameter `gcs` of the `collect` hit: `G111` after full consent, `G101` for measurement only (values seen in tests); (3) no `_ga*` or `_gcl_*` cookie before consent; (4) second page after consent: `default`, `update`, `ccm_consent_ready`.

## Declaring a service from another module

A third-party module (payment, chat) declares its cookies with a `ccm.service` tag, without depending on CookieConsentManager. The tag is a string, no PHP interface is imported, and the tag is ignored when this module is absent. The example works from Thelia 3.0 to 3.3 (tested on 3.0). The third-party module also needs `Config/module.xml` and `Config/config.xml`.

```php
<?php
// local/modules/Payzen/Payzen.php
declare(strict_types=1);

namespace Payzen;

use Symfony\Component\DependencyInjection\Loader\Configurator\ServicesConfigurator;
use Thelia\Module\BaseModule;

final class Payzen extends BaseModule
{
    public const DOMAIN_NAME = 'payzen';

    public static function configureServices(ServicesConfigurator $services): void
    {
        $services->load(self::getModuleCode().'\\', __DIR__)
            ->exclude([__DIR__.'/I18n/*'])
            ->autowire()
            ->autoconfigure();

        $services->set('payzen.ccm.antifraud', \stdClass::class)
            ->tag('ccm.service', [
                'key' => 'payzen_antifraud',
                'name' => 'Payzen anti-fraud',
                'controller' => 'Lyra Network',
                'purpose' => 'essential',
                'strictly_necessary' => true,
                'justification' => 'Payment security cookie, required to prevent card fraud.',
                'policy_url' => 'https://payzen.eu/privacy',
                'cookies' => [['name' => 'payzen_fp', 'domain' => '.payzen.eu', 'duration_days' => 1]],
            ]);

        $services->set('payzen.ccm.tracking', \stdClass::class)
            ->tag('ccm.service', [
                'key' => 'payzen_tracking',
                'name' => 'Payzen conversion tracking',
                'controller' => 'Lyra Network',
                'purpose' => 'analytics',
                'strictly_necessary' => false,
                'policy_url' => 'https://payzen.eu/privacy',
                'script' => 'https://static.payzen.eu/track.js',
                'cookies' => [['name' => 'payzen_conv', 'domain' => '.payzen.eu', 'duration_days' => 90]],
            ]);
    }
}
```

- `Config/module.xml`: `<fullnamespace>Payzen\Payzen</fullnamespace>`, title, `<version>`, `<type>classic</type>`, `<thelia>` (minimum version). Use this module's file as a model.
- Thelia 3.0 to 3.2 require a `Config/config.xml` in the module, even an empty one with the `<config>` root of `thelia-1.0.xsd`. Without it `module:activate` succeeds silently, then the whole site returns a 500 and `cache:clear` fails.

  ```xml
  <?xml version="1.0" encoding="UTF-8" ?>
  <config xmlns="http://thelia.net/schema/dic/config"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://thelia.net/schema/dic/config http://thelia.net/schema/dic/config/thelia-1.0.xsd">
  </config>
  ```

- Declare through `configureServices`, a static method of `BaseModule` present from 3.0 to 3.3. Thelia does not load a module `Config/services.php`.
- Required attributes: `key` (unique), `name`, `controller`, `purpose`, `policy_url`. A tag that lacks one is ignored, and `ccm:services:sync` prints why.
- `strictly_necessary` (default `false`) is the only way to use `purpose: essential`. It requires `justification`, shown in the back-office with a permanent alert.
- A missing `script` makes a declarative service: it is listed at the second level and its state is pushed to the `dataLayer`.
- A `key` already in the catalogue, or already declared by another module, is refused and reported in the same way.
- `controller` and `policy_url` are read by the panel and the placeholder. Each cookie can carry `duration_days` (0 for a session cookie), shown as "name (duration)".
- A service declared by a module is never eligible for the consent exemption.
- A compiler pass collects the tags and writes nothing to the database at compile time. The service enters the draft as "proposed" at module activation and update, at `php Thelia module:refresh`, at `php Thelia ccm:services:sync`, or when an administrator with the UPDATE right opens "Purposes and services". It stays inactive until an administrator enables it and publishes. It appears under "Services proposed by other modules".

## Adding alerts and validation rules from another module

The dashboard alerts and the draft validation are built from tagged services, so a module can add its own without changing this one. In a module whose services are autoconfigured (the default in Thelia 3), implement an interface and the service is picked up:

```php
final class MyAlerts implements \CookieConsentManager\Admin\AlertProvider\AlertProvider
{
    public static function priority(): int
    {
        return 50; // higher runs first; the built-in providers use 100 to 1000
    }

    public function alerts(array $draft): array
    {
        return [new \CookieConsentManager\Admin\Alert(\CookieConsentManager\Admin\Alert::WARNING, 'my_alert', 'Message', 'ccm_admin_services')];
    }
}
```

- `AlertProvider` (tag `ccm.alert_provider`) returns the alerts of the normalized draft. The dashboard sorts all alerts by severity (danger, warning, info) and keeps the order of the providers inside a severity. Use a stable `code`: it is the identifier of the alert in the page.
- `SectionValidator` (tag `ccm.section_validator`) returns the `ValidationIssue` list of one part of the draft (`validate(array $draft): array`). An issue of severity `error` blocks the save and the publication, and a `warning` does not. Built-in sections run at priorities 600 to 1000.
- `priority()` is read when the tag carries no `priority` attribute. To set it from the service definition, tag the service yourself: `->tag('ccm.alert_provider', ['priority' => 50])`.
- Messages are your own: translate them in your module. The module does not extract them.

## Content Security Policy

What the module emits and what to allow:

- An inline script at the top of the page (no nonce): `script-src 'unsafe-inline'`, or a hash of the inline script, which changes with each module version.
- The stylesheet is a file of your own origin (`style-src 'self'`). The banner and the panel still carry the colours of the Appearance screen in a `style` attribute, so `style-src 'unsafe-inline'` (or `style-src-attr 'unsafe-inline'`) stays needed when you customise them.
- The engine script is same-origin (`script-src 'self'`).
- The panel is fetched from the same origin (`connect-src 'self'`).
- Choices are recorded with `POST /ccm/consent`, same-origin (`connect-src 'self'`).
- The engine uses neither `eval` nor `unsafe-eval`.
- Restored scripts (the `text/plain` scripts you tag, and the code of `custom` services) are inline scripts recreated by the engine. Under a strict CSP without `unsafe-inline`, put a `nonce` on the original tag (the engine copies it to the restored script) or use `strict-dynamic` on the site side.
- Enabled services load their own domains: add them to `script-src`, `connect-src`, `img-src` and `frame-src` as the service needs. The domains a service contacts are in the `domains` field of `Resources/catalogue/catalogue.json` (filled for verified services only, and not for the self-hosted Matomo). The Verification also reveals them. Third-party cookies and iframes stay blocked by the module until consent is given.

The endpoint answers 403 `forbidden_origin` to a POST whose `Origin` is not the current host, whose `Sec-Fetch-Site` is neither `same-origin` nor `none`, or that carries neither header. Do not proxy it to another domain, and send these headers in a `curl` test.
Behind a reverse proxy or a CDN, declare the proxy in `framework.trusted_proxies`, or the rate limiter (120 requests per minute) counts all visitors together.

The statistics are indicative and the endpoint is not authenticated: an HTTP client that forges POST requests with a new `consent_id` inflates the first-choice counts, within the per-address rate limit. The registry records the source of each choice.

## Tests

The module is tested inside a Thelia 3 site, because it needs the core and the generated Propel models.

| What | Command |
|------|---------|
| JavaScript (engine, compatibility layer, served script) | `npm install && npm run test:js` at the module root (`node --test tests/js/*/*.test.mjs`). The server serves `assets/js/*.min.js`: after any change to `compat.js`, `engine.js` or `head.js`, run `npm run build` and commit the minified files (a test fails when they are stale). After a change to the catalogue fragments, `node tools/catalogue/embed-rules.mjs` regenerates the iframe rules |
| PHP unit and integration tests | from the shop root, against a test database: `vendor/bin/phpunit -c local/modules/CookieConsentManager/phpunit.xml.dist`. The bootstrap refuses any database whose name does not contain `test` (`bin/test-prepare` builds one). With DDEV: `ddev exec 'cd /var/www/html && DATABASE_NAME=test vendor/bin/phpunit -c <module path>/phpunit.xml.dist'` |
| PHPStan (level 6) | `CCM_SITE_ROOT=$PWD vendor/bin/phpstan analyse -c local/modules/CookieConsentManager/phpstan.neon.dist --memory-limit=1G` from the shop root |
| Code style | `vendor/bin/php-cs-fixer check --config=.php-cs-fixer.dist.php` from the module root (rule set of the Thelia core) |
| Regenerate the catalogue (maintainers) | `npm run catalogue:build`, see [maintaining the catalogue](maintaining-the-catalogue.md) |

PHPUnit, PHPStan and php-cs-fixer are not dependencies of the module. Install them next to the shop, or in a throw-away directory (`composer require --dev phpunit/phpunit:^11.5 phpstan/phpstan:^2.1 friendsofphp/php-cs-fixer:~3.93.1`). php-cs-fixer 3.95 removes the `declare(strict_types=1)` lines with this rule set, hence the pin.

Browser checks to replay on an integrated theme:

1. Clean browser: no request to a service domain before a choice; `default` denied in `dataLayer`.
2. "Reject all": no new request, only `ccm_consent` is set.
3. A tagged `text/plain` script runs only after consent, including after a reload.
4. Overridden template: the marker `{# ccm-templates:1 #}` is present, the `data-ccm-*` attributes are present, no red alert on the dashboard.
5. Module disabled then enabled again: the page answers 200 thanks to the guard, and the registry is intact.
6. Mobile, 375 px: the banner does not cover the "Add to cart" button and stays under 38% of the screen height.
